# Naruto 导入数据

将用户要求的文件变更转换为 Naruto 导入数据。当前对应 vscode-naruto 0.2.0 的 **工作区协议 v1**。使用随 skill 安装的脚本编码，不能凭空编写压缩串。

主要任务是**生成要导入回去的新操作**：可以从用户的需求和新文件直接开始，无需先导出工作区。读取已有导出只是获得修改上下文的一种可选方式。

## 准备修改

- 读取 [协议与操作规则](references/protocol.md)，确认目标 VS Code 工作区的准确名称、相对路径及用户要求的修改。
- 工作区名称采用用户明确指定的目标；未指定时从用户提供的快照或目录结构确定。mac 接收助手的目录结构为 `resources/<workspace>/…`，其中 `resources` 只是容器。本机任务目录名称不一定是远端工作区名称；无法确定时询问用户，不猜测。
- 新增文件：生成完整新内容，用 `create` 表达目标必须不存在的意图，或在用户要求覆盖时用 `write`。删除、重命名和新建目录可直接从明确的工作区与路径构造 `delete`、`rename`、`mkdir`，无需文件内容或历史导出包。
- 修改已有文件需要完整原文。可解码完整导出文本，或读取用户提供的 JSON、导出目录或压缩包。片段不足以还原完整文件时，先获取缺少的内容。
- 如果用户提供完整压缩文本，先保存为文件，再执行下面的 `decode`。导出起始元信息不属于压缩文本；尚未收齐的分块不能当成完整输入。
- 编辑导出副本或生成修改后的完整文件，再构造操作包。只包含此次要求的变更，保留原工作区名、相对路径及未涉及的文件内容。`write` 是整文件覆盖，不是补丁；不能把 diff、占位符或“其余不变”放入 `content`。
- `delete` 和 `rename` 仅用于用户要求的删除与重命名。只从快照中省略文件不会删除远端文件。不把解压后缺失、不可读或未知的文件自动解释为删除。

## 编码与校验

脚本只需要 Node.js 18+；不依赖当前项目、VS Code、pnpm 或另行安装 npm 包。将下面的 `<skill-dir>` 替换为本次读取的 `SKILL.md` 所在目录，路径需正确引用。

将新操作编码为可回写的结果：

```sh
node "<skill-dir>/scripts/naruto.mjs" encode changes.json changes.naruto.txt
```

仅在需要读取已有压缩包时，执行辅助解码（导入操作包和导出快照都可解码）：

```sh
node "<skill-dir>/scripts/naruto.mjs" decode input.naruto.txt decoded.json
```

`encode` 校验操作包，并在写出前执行解码回验；`decode` 解压并校验协议。省略输出文件时输出到 stdout。失败时报告 stderr 原因并修正输入，不能将失败输出称为可导入结果。

将修改后的文件内容通过文件 IO 放进 `changes.json`；生成 JSON 时使用 JSON 序列化函数，避免引号、换行或二进制编码被手工拼接破坏。脚本校验结构，不会连接目标工作区，也无法检查远端文件是否存在、是否未保存或工作区名称是否匹配。

## 交付

- 输出简短的工作区与操作摘要，并提供生成的 `changes.naruto.txt` 文件链接。需要审阅时也提供 `changes.json`。
- 压缩串较短时，可以从输出文件完整读取后放进一个 `text` 代码块，便于直接复制。代码块内仅包含完整压缩串，不附元信息、序号、注释或省略号；过长则只交付文件，不能截断。
- 告知用户：**复制 `.naruto.txt` 文件的完整文本内容**到剪贴板，再点击 VS Code Naruto 虚拟工作区的 **导入**。复制文件对象或 ZIP 文件不能用于这里的导入。
- 默认交付数据，不自动点击导入。用户明确要求复制到剪贴板时可复制生成的完整文本；明确要求实际导入时按已有授权执行。只有实际执行并验证导入后，才能说远端工作区已修改。
- 涉及覆盖、删除或重命名的未保存文档需先保存或撤销编辑。导入按顺序执行且不具有事务性；失败后根据已应用的操作数量检查状态，再生成剩余操作，不能直接假设整包重试安全。
