# Naruto

Naruto 提供 Brotli + Base91 文本压缩，以及直接关联真实文件的虚拟工作区。

要求 VS Code 1.72.0 及以上版本。

## 虚拟工作区

在资源管理器中右键文件或文件夹（支持多选），或右键文件 Tab，选择 **添加到 Naruto 虚拟工作区**。活动栏的 Naruto 入口会打开虚拟工作区文件树，选择项随当前 VS Code 工作区保存。

- 点击文件可打开原文件并编辑。右键菜单支持新建文件、新建文件夹、重命名和删除，操作直接应用于真实工作区。
- **从 Naruto 虚拟工作区中移除**只隐藏选择项，保留真实文件；也可以单独移除已选目录内的子文件或子目录。
- 资源管理器和文件 Tab 的右键菜单会按右键目标的状态显示“添加”或“移除”，包含已选目录内的子项，以及被单独移除的子项。
- 命令面板提供 **将当前文件添加到 Naruto 虚拟工作区**、**将当前文件从 Naruto 虚拟工作区中移除**。
- 顶部保留筛选、导入、导出按钮。**更多（…）**菜单收纳排序、新建文件/文件夹、刷新和清空列表。**清空 Naruto 虚拟工作区**（命令：`naruto.virtualWorkspace.clear`）也可从命令面板执行，二次确认后清空全部选择记录并取消当前导出，保留真实文件。
- VS Code 中的重命名会同步更新虚拟列表；文件新增或删除会刷新文件树，也可以点击标题栏的刷新按钮。
- 更多菜单中的新建操作允许选择真实工作区作为新文件或文件夹的位置。

### 排序与文件名筛选

更多菜单支持两种排序，选择随当前工作区保存：

- **按添加顺序**（默认）：顶层项保留加入虚拟工作区的先后顺序。
- **按实际文件顺序**：顶层项按文件夹优先、名称自然排序，例如 `file2` 在 `file10` 前。展开目录内的子项始终使用此顺序。

顶部筛选按钮打开原生输入框，提供区分大小写（Aa）、全词匹配和正则表达式切换。输入时预览结果，Enter 保留，Esc 或失焦取消本次修改；输入框中显示各开关状态，非法正则会显示错误并阻止确认。筛选条件与开关随工作区保存，也可以在更多菜单中清除筛选。

筛选只匹配文件名，保留命中文件所需的父目录并自动展开。打开筛选会取消原选中状态；筛选期间顶部导出只导出匹配文件，重新选中文件夹时也不会导出其中不匹配的文件。匹配文件使用各自的导出模式。没有匹配文件时提示错误，不会回退到全量工作区。筛选不会把隐藏项从虚拟工作区中移除。

## 分块导出与导入

在文件树中可多选文件和文件夹。点击任意**已选中项**的行内导出按钮，或点击**顶部导出按钮**，都会导出整个选中范围。点击未选中项的按钮只导出该项；顶部按钮在没有选择项时导出整个虚拟工作区。文件夹递归导出内容，保留原工作区路径并跳过已移除的子项；父文件夹和子项同时选中时，以父文件夹为准，避免重复。

同一范围重复点击会继续复制下一块；选择范围改变后重新从起始元信息开始。底部状态栏始终继续已经冻结的当前快照。导入统一使用顶部入口。

1. 点击虚拟工作区标题栏的 **导出**。Naruto 递归读取选中文件夹，生成一份固定快照，首次仅将 **起始元信息块**（明文 JSON）复制到剪贴板。它包含后续数据分块数量和完整压缩文本的校验和。
2. 粘贴元信息，再点击导出按钮或底部状态栏复制第 1 个数据块，之后每次点击只复制下一个数据块。状态栏从 `0/N · 元信息已复制` 开始，显示 `已复制数据块数/数据块总数`；元信息不计入数据块数量。旁边可取消剩余复制，取消保留当前剪贴板，下一次导出重新生成快照并从元信息块开始。
3. 接收端按元信息中的数量收齐数据块，按顺序拼接并校验完整性（规则见下文）。元信息不参与拼接。交给 Naruto 解压时数据块可以用换行分隔，不添加编号或其他字符。
4. 外部使用 Naruto 原有解压方式得到下述 JSON，修改内容或动作，再使用原有压缩方式得到完整文本。现有 **Open Compression Webview** 也可以完成这一过程。
5. 将完整压缩文本放入剪贴板，点击标题栏的 **导入**。Naruto **只读取一次剪贴板**，解压后按操作顺序应用至真实工作区。

`naruto.virtualWorkspace.chunkSize` 控制每个数据块的字节数，默认 **256**，独立于普通文本压缩设置。起始元信息始终作为一个完整块复制，不受该大小限制。Base91 输出仅含 ASCII，因此每个字符恰好占一个字节。元信息和数据块来自同一次快照，导出期间的后续文件修改不会影响本次传输。最后一个数据块复制后即完成导出，再次点击会开始新快照。

### 起始元信息块（版本 1）

起始块为未压缩的 JSON，格式如下（`checksum.value` 为占位说明）：

```json
{
  "format": "naruto-virtual-workspace-export",
  "version": 1,
  "chunkCount": 3,
  "chunkSize": 256,
  "byteLength": 600,
  "checksum": {
    "algorithm": "sha256",
    "value": "<64 位小写十六进制摘要>"
  }
}
```

- `chunkCount`：后续数据块数量，不包含元信息块。接收端可用 `已接收数据块数/chunkCount` 显示进度，收到指定数量后结束接收。
- `chunkSize`：每个数据块的最大字节数，最后一块可以不足此长度。
- `byteLength`：全部数据块按顺序直接拼接后的总字节数。
- `snapshot`（新版导出）：与压缩包内一致的快照标识；`base` 存在时表示依赖的旧基线。接收器在收到起始块后立即检查对应副本，缺失时停止接收并提示手动切换全量模式。
- `checksum`：对 **完整 Base91 压缩文本的 UTF-8 字节**计算 SHA-256，输出小写十六进制摘要。计算时不包含元信息，也不插入换行、空格或其他分隔符。

接收端将数据块用 `chunks.join("")` 拼接，核对总字节数，并比较 `SHA256(UTF8(拼接文本))` 与 `checksum.value`；匹配后再解压。此校验在收齐后检查整份数据，可发现缺失、内容变化或顺序错误。导入仍只读取一次剪贴板，剪贴板中应放校验后的完整压缩文本，不包含起始元信息。

## 外部交换格式（版本 1）

全量导出包含当前内容，增量导出包含相对基线的变化，不记录本地动作历史。文件使用 `write`，目录使用 `mkdir`（包括空目录），删除使用 `delete`。混合模式包的可选 `replace` 列出全量项范围，Mac 接收器复制基线后先清空这些范围，再应用本次操作，从而完整替换全量项。外部可修改操作记录或添加操作。

```json
{
  "format": "naruto-virtual-workspace",
  "version": 1,
  "operations": [
    {
      "action": "write",
      "workspace": "my-project",
      "path": "src/index.ts",
      "encoding": "utf8",
      "content": "console.log('Naruto');\n"
    },
    {
      "action": "mkdir",
      "workspace": "my-project",
      "path": "src/features"
    },
    {
      "action": "create",
      "workspace": "my-project",
      "path": "src/features/new.ts",
      "encoding": "utf8",
      "content": "export const enabled = true;\n"
    },
    {
      "action": "rename",
      "workspace": "my-project",
      "path": "src/old.ts",
      "to": "src/renamed.ts"
    },
    {
      "action": "delete",
      "workspace": "my-project",
      "path": "src/unused.ts"
    }
  ]
}
```

| 动作 | 行为 |
| --- | --- |
| `write` | 创建或覆盖文件；`encoding` 为 `utf8` 或 `base64`，`content` 为对应字符串。自动创建父目录。 |
| `create` | 新建文件；字段同 `write`，同名文件存在时失败。 |
| `mkdir` | 创建目录及父目录；已有目录保持原状。 |
| `rename` | 将文件或目录移动到同一工作区的 `to` 相对路径；目标父目录应已存在，不覆盖已有目标。 |
| `delete` | 删除真实文件或递归删除真实目录。 |

`workspace` 必须与当前打开的某个真实工作区根目录的名称唯一匹配。多根工作区以名称区分，导入到另一份副本时可修改该字段。路径使用 `/` 分隔，不能使用绝对路径或 `..`；`.` 仅用于根目录的 `mkdir` 记录，不能删除或重命名真实工作区根目录。

操作按数组顺序执行。重命名后的内容修改应使用新路径；从数据包中省略某个文件不会删除它，删除必须写明 `delete`。导入成功的项目会出现在虚拟列表中。

文本按 UTF-8 导出，二进制内容按 Base64 无损导出。打开且未保存的文本使用编辑器当前内容；导入遇到会覆盖、删除或重命名未保存文档的操作时，会要求先保存或撤销编辑。符号链接暂不参与导出，导入路径也不能经过符号链接。

压缩方式与原有 Naruto 一致：先将数据包 `JSON.stringify` 成字符串，再交给 `compress-brotli` 的默认 `compress`，最后 Base91 编码。解压执行相反步骤。注意 `compress-brotli` 默认还会对输入字符串做自身的序列化，直接压缩 JSON 的原始字节并不等价。

导入前会校验整个数据包的格式、路径、工作区和未保存文档。文件操作不具有事务性；若后续操作因文件不存在、目标冲突或 IO 错误失败，会停止并报告此前已应用的操作数量。

## 开发与验证

```sh
pnpm install --frozen-lockfile
pnpm run compile
pnpm test
```

测试在独立临时工作区中运行，覆盖文件操作、导入导出与剪贴板分块。可设置 `VSCODE_EXECUTABLE_PATH` 使用已有 VS Code 可执行文件，避免下载测试版本。

### 导出模式与基准

每个文件/文件夹可在右键菜单中切换 **增量导出模式** 或 **全量导出模式**，支持对多选项一起设置。模式随工作区保存，VS Code 内重命名后继续保留。增量项名称前显示 `diff` 图标，悬停提示当前模式。选中的文件夹决定其整个递归范围的模式；子项独立设置用于单独选择该子项导出时。

同一多选范围允许混合模式：全量项发送当前完整内容并在接收端替换对应范围，增量项只发送新增、修改和删除。整体工作区、单个节点、每组多选范围分别维护基准；多选顺序和重叠子项不影响范围身份。范围首次没有发送端基准时，发送全量包建立基准。

实际不依赖旧基线的包，最后一个数据块复制成功后**自动记录基准，不弹接收确认**。取消或未完成复制不推进基准。发送端显示“复制完成”，不据此宣称已接收。若接收端实际没有收到副本，后续增量会在起始块检查时被拒绝；请取消发送端当前导出，选中范围内项目并右键切换到全量模式，再重新导出。

实际依赖旧基线的增量或混合包，最后一个数据块复制后提示“接收成功 / 接收失败”。请先在 Mac 看到接收成功和完整文件列表，再确认成功以推进基准。失败或关闭提示不更新基准。发送期间修改的内容留到下一次导出。命令面板仍保留一次性“全量导出 Naruto 虚拟工作区”入口。

`naruto.virtualWorkspace.deleteRemoved` 默认为 `true`：从虚拟工作区移除资源时，下次增量包生成 `delete` 操作，但不删除发送端真实文件。关闭后，只有真实路径已经不存在的资源才生成删除操作；成功确认后，已移出选择的资源不再跟踪。全量项始终按本次范围完整替换。

传输只发送增量，Mac 接收助手根据包内的基线标识读取已保存副本，应用新增、修改和删除，自动恢复完整目录；“复制压缩包”提供的仍是完整包，AI 无需处理差异。接收端副本保存在 `~/Library/Application Support/NarutoReceiver/Snapshots`，重启后仍可使用；界面中打开和编辑的是单独的临时副本，不会污染基线。旧基线保留以支持接收成功但发送端未确认后的重传。

插件和接收助手需一起更新；旧版没有基线标识的数据仍可作为独立全量快照接收。
