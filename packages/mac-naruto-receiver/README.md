# mac-naruto-receiver

Naruto 的原生 macOS 导出接收助手，使用 AppKit、SwiftUI、CryptoKit 和系统 Compression 框架，无第三方运行时依赖。要求 macOS 13+。

从仓库根目录运行：

```sh
pnpm start:mac       # 构建并打开 .app
pnpm package:mac     # 仅构建 .app
pnpm test:mac        # 协议、解压及 ZIP 测试
```

也可在本目录运行 `swift build` 或 `swift test`。实际使用推荐运行 `.app`，以便系统对应用进行辅助功能授权。详细操作见[仓库文档](../../README.md)。

`swift test` 需要完整 Xcode 中的 XCTest。未将 Xcode 设为默认开发目录时，可通过 `DEVELOPER_DIR=/path/to/Xcode.app/Contents/Developer` 指定工具链。

## 接收行为

- 窗口顶部按“接收”和“自动点击”分组，标签与控件统一对齐，说明显示在对应控件下方。“点击后切换应用”使用开关，开启后才显示切换方式。手动模式隐藏自动点击设置。选择会自动保存，接收期间不能切换。
- 全局快捷键 **⌘⇧E** 开始或取消。两种手动模式也可直接点击窗口中的开始按钮，不依赖 VDI 是否拦截快捷键。
- 手动监听时，每次点完导出可直接用 **⌘Tab** 切到另一个本地应用，触发失焦同步。**⌘⇧R** 或菜单栏“请求显示接收器”也可请求激活接收器；若系统拒绝此请求，请直接手动切换窗口。这些操作不会点击导出，也不会取消接收。
- 自动模式先激活目标窗口，将鼠标放到导出按钮上再按快捷键。起点使用 Quartz 屏幕坐标，进度浮窗使用 AppKit 屏幕坐标，支持多显示器。
- 监听期间主动请求剪贴板文本，使用系统 `NSString` 文本转换读取 UTF-8 / UTF-16 等格式。内容变化或 `changeCount` 变化均视为新数据，兼容同一所有者下的延迟更新；新所有者写入相同文本仍接收一次。整个接收过程保留同一读取位置，避免漏掉两次等待之间的手动复制。
- 手动粘贴模式完全不轮询剪贴板，使用原生文本输入框接收用户的 **⌘V** 粘贴；每次提交严格按一块处理，复用相同的协议校验和解压流程。
- 每次仅发出一次单击；超时、非法分块或取消后停止，不自动重试。总数据块数量来自版本 1 元信息，收齐后不再点击。
- 校验分块长度、Base91 字符和最终 SHA-256，按 `Base91 → Brotli → JSON 字符串 → 工作区 JSON` 解码，兼容 `compress-brotli` 默认的二次序列化。
- 接收插件导出的全量或增量快照。起始数据头包含基线标识，收到后立即检查本地副本；缺少时停止接收，提示取消当前导出并在 VS Code 右键切换全量模式重导。混合模式先替换全量项范围，再应用 `write` / `mkdir` / `delete`，恢复完整目录。写入前校验工作区名称、路径和快照标识。
- 完整副本持久保存在 `~/Library/Application Support/NarutoReceiver/Snapshots/<快照标识>/`，应用重启后继续使用。保留旧基线以支持重传；删除这些副本后需要重新全量导出。
- 浏览和编辑使用 `$TMPDIR/naruto-<UUID>/resources/<workspace>/…` 下的独立副本，ZIP 位于同一临时根目录下；本地编辑不会污染增量基线。复制的 ZIP 始终包含恢复后的完整目录，AI 无需额外处理差异。
- 恢复完整文件包并保存副本后，接收端显示“接收成功”。依赖旧基线的增量或混合包，还需在 VS Code 中确认接收成功以推进基准；全量包复制完成后发送端自动记录基准，无需确认。
- 文件区支持 **列表 / 树状** 切换，默认树状，选择自动保存。列表只列文件并显示完整相对路径；树状以工作区为根，按目录层级展示，目录内文件夹排在前面。工作区默认展开，单击文件夹名称或箭头展开、折叠子目录，空文件夹也会显示。
- 单击文件使用系统默认应用打开；文件夹在树状视图中单击展开，右键仍可在默认应用中打开或在 Finder 中显示。右键复制文件的文本内容，二进制内容转为 Base64；复制 ZIP 使用 `NSPasteboard.writeObjects([NSURL])`，供支持文件粘贴的应用使用。
- 再次复制压缩包时会重新压缩当前文件，包含用户通过结果列表打开后保存的修改。

协议 v1 的数据块没有序号，只能在收齐后用整包校验发现乱序或同长度的剪贴板干扰。接收时应避免其他复制操作；失败后先取消 VS Code 端的导出再重新开始。

## 深信服 / 其他 VDI 的点击选项

| 接收方式 | 行为 |
| --- | --- |
| 自动 · 登录会话（默认） | 使用会话事件源，投递到当前登录会话入口。深信服优先尝试此方式。已有选择会保留。 |
| 自动 · 系统级 HID | 使用 HID 事件源，将鼠标移动、按下、抬起投递到系统事件入口。 |
| 自动 · 指定进程 | 将事件直接发给按快捷键时的前台应用。先激活 VDI 客户端，目标进程在本次接收中保持固定。 |
| 手动点击 · 仅监听剪贴板 | 不模拟点击、不需要辅助功能权限。先启动监听，再手动点远端导出按钮；看到进度增加后再点下一块。 |
| 手动粘贴 · 逐块接收 | 不模拟点击、不监听剪贴板。手动点远端导出，在接收窗口输入框中按 ⌘V，再点“提交这一块”。先提交起始元信息，再逐块提交。 |

自动方式都属于 macOS 合成事件，不保证所有深信服客户端版本或输入设置都接收。优先用 **登录会话**；点击无效时再试其他自动方式或手动点击。切换方式前结束当前接收，并取消 VS Code 中未完成的导出，从起始元信息重新开始。

### 失去焦点后才同步剪贴板

若远端点完导出没有进度，而切到本地窗口才收到数据，开启 **点击后切换应用**。此开关默认关闭，选择会保存。深信服建议搭配 **登录会话 + 常规 + 系统快捷键 · ⌘Tab**。

| 切换方式 | 行为 |
| --- | --- |
| 系统快捷键 · ⌘Tab（默认） | 通过系统应用切换器切到上一个本地应用，不要求 Receiver 获得焦点。保留另一个本地应用，接收期间不要手动切换应用。 |
| 应用激活 | 请求 macOS 激活接收器浮窗。若出现“未能切换到 Naruto Receiver”，改用系统快捷键方式。 |

开启后，起始元信息和每个分块均按以下流程接收：

1. 确认按 ⌘⇧E 时记录的原目标应用在前台，之后每块接收前通过所选方式切回。
2. 在固定位置单击，等待远端处理（按节奏分别等待 150 / 500 / 1000 ms）。
3. 使用 ⌘Tab 切到上一个本地应用（旧方式则请求激活进度浮窗），确认原 VDI 已失焦。主窗口暂时隐藏，浮窗继续显示进度。
4. 收到新剪贴板文本后，才使用 ⌘Tab 返回原 VDI（旧方式则请求激活原应用）。确认是原进程在前台后再点击；收齐后直接显示结果。

每次焦点转换只发送一次快捷键，不遍历其他应用。切换被拦截、切回了错误应用、同步超时或取消时停止，不继续点击。开启此选项时焦点会自动往返，接收期间请保持目标窗口及导出按钮位置不变。如果复制尚未完成就切出了窗口，可改用 **慢速**，增加点击后的等待时间。若 VDI 拦截了 macOS 的 ⌘Tab，改用手动监听并手动切换到其他本地窗口。

手动监听不自动往返切焦点：每次手动点击远端导出后按 **⌘Tab**，等进度增加，再返回 VDI 点击下一块。窗口里的“显示接收器”按钮、⌘⇧R 和菜单栏入口可请求显示接收器，但系统不保证接受后台激活请求。

| 点击节奏 | 点击前间隔 | 按住时长 | 每块剪贴板等待 |
| --- | --- | --- | --- |
| 更快 | 150 ms | 25 ms | 10 秒（起始元信息 30 秒） |
| 常规（默认） | 500 ms | 120 ms | 30 秒 |
| 慢速 | 1 秒 | 200 ms | 60 秒 |

节奏名称调整为“更快 / 常规 / 慢速”，原有等待参数和已保存的选择保持不变。

每次自动点击前先发送鼠标移动事件，并始终发送抬起事件，包括按住期间取消的情况。点击完成后等待剪贴板确认，再发出下一次点击；节奏选项不会开启不等确认的盲目连点。

两种手动模式不设每块超时，可等待剪贴板延迟同步或停下来查看进度；通过快捷键或窗口的 **取消接收** 停止。监听模式不会接收开始前剪贴板里的旧内容；粘贴模式只接收明确提交的文本。请勿连续快速点击多次，剪贴板只保留最后一次值，助手无法恢复被覆盖的分块。

若 **Mac 可以粘贴、监听却没有进度**：

1. 先切到本地窗口；若此时收到数据，自动模式开启 **点击后切换应用** 并选择 **系统快捷键 · ⌘Tab**，手动模式每次点击后手动切换窗口。需要进一步排查时，展开 **剪贴板诊断** 查看所有者计数、可用类型和读取字节数；诊断不显示文本内容。
2. 若 macOS 禁止了应用后台读取剪贴板，按错误提示在系统设置中允许，或直接选择 **手动粘贴 · 逐块接收**。
3. 粘贴模式中，点击 **开始粘贴接收**，手动点远端导出，在输入框按 **⌘V** 并提交起始元信息，再重复点击、粘贴、提交，直到文件还原。

`changeCount` 只记录剪贴板所有权变化，不保证每次内容变化都递增（[Apple 文档](https://developer.apple.com/documentation/appkit/nspasteboard/changecount)）。主动读取可处理不更换所有者的内容更新；若客户端连相邻相同分块也不更新所有者，原始协议无法自动区分新旧数据，此时用逐块粘贴。若 Mac 本机也无法粘贴远端文本，则需先处理 VDI 的剪贴板共享设置。

## 源码与测试

- `Sources/NarutoReceiver`：菜单栏应用、快捷键、鼠标与剪贴板采集、SwiftUI 窗口。
- `Sources/NarutoTransfer`：协议解析、校验、解压、增量合并、持久化副本和 ZIP 创建。
- `Tests/NarutoTransferTests`：跨语言固定样本、相邻重复块、校验失败、不安全路径、文件内容和归档测试。
- `Tests/NarutoReceiverTests`：旧剪贴板排除、相同文本的新写入、所有者不变的文本更新和延迟数据、UTF-16 文本、模拟失焦后发布数据、切回错误应用或未知焦点时停止、手动模式及取消等待。焦点测试注入模拟前台进程和快捷键发送器，不会切换真实桌面。

固定样本由 `packages/vscode-naruto/scripts/receiver-fixtures.mjs` 调用插件真实编码器生成。自动测试不发送真实鼠标事件。桌面验收需授权辅助功能后，在 VS Code 的导出按钮上验证快捷键、浮窗、取消、文件打开和 ZIP 粘贴。
